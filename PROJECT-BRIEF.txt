I want to create a site called insight-retreats.org which catalogues and labels retreat centers in the United States. The retreat centers and their descriptive entries are generated by Claude instances. I have a harness which utilizes sub-agents to locate retreat centers in a given area and write a descriptive entry about them using web search and a preset format. The entries are saved and displayed on the website. The site has a list view of retreat centers within a certain geography, and a map view showing them as pins that can be clicked to see their geographic location. It's a plain static site (no backend), so it can be hosted for free on any static host such as GitHub Pages or Cloudflare Pages. We're limited to California to begin with. We include all traditions, Goenka centers included (there's a `goenka` tag for them).

Each entry has: center tradition / technique / influences, teacher access, retreat options (possible lengths of stay), retreat schedule, retreat cost, is food served, is work required, and a standardized system of applicable tags/labels. Additional decisions since: cost is shown as a prominent per-night $ figure with a `~` (e.g. `~$245–$370 / night`) based on a standard multi-day / weeklong retreat, excluding scholarships, donation floors, and one-time/day events, with a source link — the amount is prominent and the `/ night` unit is a smaller muted suffix; when no price is determinable the entry omits `pricePerDay` and the site shows `~$?/night`; strictly donation-only centers show `Donation-based`. Food has a type (vegan / vegetarian / omnivore) shown as a green badge on the "Food served" line — there is no separate diet row. There's a one-paragraph "about" (the only paragraph — everything else is concise). A center qualifies for inclusion only if it offers an overnight residential stay of **two nights or more** at that location (day-only venues are excluded). Clean, blue aesthetic matching freefall.quest (light translucent header, serif Georgia body, Playfair headings, "New Rocker" wordmark reading `insight-retreats.org`, bold blue intro line "A map of insight meditation centers across the United States." shown only on the main page, sticky footer reading "Entries are written by Claude, an AI assistant, from public sources, and may be out of date or contain errors.").

* The harness is Cowork-native: just tell Claude "add retreat centers in <region>" and Claude acts as an **orchestrator** — it does NOT do the web research itself. It (1) reads the existing `data/centers/*.json` names + `aka` to build an exclusion list; (2) spawns a dedicated **discovery sub-agent** (one per region for big areas) that web-searches for real, currently-operating centers and returns a vetted candidate list, skipping anything already catalogued; (3) spawns **one research sub-agent per new center** that researches it and writes candidate JSON to `data/_staging/<slug>.json` (the orchestrator hands each sub-agent the exact `id`/slug to use); then (4) runs `node scripts/ingest-center.mjs` (validates, registers any ad-hoc `proposedTags` into the master `schema/tags.json`, writes clean entries to `data/centers/`, clears staging, rebuilds `public/data`). Hard rules baked into the runbook: never duplicate an existing center (check `name` + `aka`), apply the two-night-minimum, and use the EXACT enum values verbatim (`foodServed`/`workRequired` in yes/no/partial/unknown; `foodType` in vegan/vegetarian/omnivore/mixed/unknown). Runbook: `harness/COWORK.md`. An optional Node/Agent-SDK CLI still exists in `harness/src/`. No API key or terminal needed for the Cowork path.
* **`ingest-center.mjs`'s validator is shallow — it only checks required keys, `id` format, `location.lat/lng` numeric-ness, and that tags exist in the vocabulary. It does NOT check field *shapes*, so bad data from a research sub-agent can sail through ingestion and silently break the live site.** Double-check these explicitly after every ingest batch (a quick node script that loads every `data/centers/*.json` and asserts the shapes below catches all of them):
  - `influences` MUST be a JSON array of short strings (`["S.N. Goenka", "Sayagyi U Ba Khin"]`), never a single sentence string — a string has `.length` (truthy) but not `.join`, so `showDetail()` throws `c.influences.join is not a function` and the entire center detail page fails to render.
  - `sources` MUST be a JSON array of `{ "title": "...", "url": "..." }` objects, never plain URL strings.
  - `workRequired` / `foodServed` MUST be exactly one of `yes`/`no`/`partial`/`unknown` — never a tag id like `no-work-required` (that's a *tag*, not a valid value for this field).
  - `pricePerDay`, when present, MUST be the full object `{ min, max, unit, notes, source }` — **never a bare number.** A bare number has no `.min`/`.max`, and the site's price-formatting code treats missing `.min`/`.max` as "no price set" and silently renders `Donation-based` — even though a real price exists.
  - After ingesting, also do a quick jsdom render check per new center id (load `index.html` with `runScripts:"dangerously"`, stub `window.L`/`window.XLSX`, inject `data.js` + `app.js`, set `location.hash = "#/center/<id>"`) to confirm the detail page actually renders with zero JS errors — this catches shape bugs the validator misses. A `Proxy`-based Leaflet stub (`const chainable = () => new Proxy({}, { get: () => () => chainable() }); window.L = new Proxy({}, { get: () => () => chainable() });`) is the fastest way to no-op every `L.*` method Leaflet might call without enumerating them one by one; also stub `window.scrollTo = () => {}` (jsdom throws "Not implemented" on it when the app sets `location.hash`) and expect a benign `DOMException` from jsdom's own hash-navigation internals even on a fully working page — that's not an app bug.
* **Pricing rule:** if the official site publishes an actual per-night (or per-retreat, divisible into per-night) dollar figure for its *ongoing residential retreat program* — not a one-time special event — use that real number in `pricePerDay` and do NOT tag the center `dana-donation` or describe it as "donation-based," even if the same center separately mentions dana for the teacher's compensation, or a different one-off program is by-donation. Dana-for-the-teacher (common at Zen/Insight centers alongside a fixed room-and-board fee) is distinct from the retreat *itself* being donation-based — only use `dana-donation`/omit pricing when the stay itself genuinely has no set fee.
* **Do one state at a time.** When asked to add several states (e.g. "do Nevada, then Oregon, then Washington"), FULLY complete one state before starting the next: discover → research → ingest → update `STATE_NAMES` → verify that state's entries render, and confirm it's done, before moving on. * **Scope: Christian contemplative centers are OUT OF SCOPE.** Catholic / Benedictine / Franciscan / Camaldolese abbeys, monasteries, hermitages, and diocesan retreat houses are excluded by the discovery + research runbook, and the `christian-contemplative` tag has been removed from `schema/tags.json`. Note: **Shasta Abbey is Soto Zen Buddhist** despite "Abbey"/"Order of Buddhist Contemplatives" in its name, so it IS in scope. Also out of scope: centers whose primary focus is yoga training (asana/physical postures) rather than meditation, even if styled as an "ashram" or "retreat center"; a Hindu/yoga-lineage center is only in scope if meditation (not asana) is the central practice retreatants come for. Devotional/pilgrimage-centered Hindu ashrams (bhakti/darshan-focused rather than meditation-focused) are also excluded on the same basis. Also out of scope: rented-venue-only retreats (the sangha must own/operate the facility itself), single-night-only "overnight" programs (need 2+ nights), and general wellness/spa/adventure lodges where meditation is a minor add-on rather than the central offering.
* **Tag vocabulary is deliberately lean.** `schema/tags.json` is the controlled list; never invent tags inline (the ingest step marks an entry INVALID and skips it if it carries an unknown tag). Removed from the vocabulary so far: `christian-contemplative`, `nondenominational-buddhist`, `interfaith`, and `residential` (every catalogue entry has it by definition, since 2+ night residential stay is the baseline qualifying criterion). Current groups: `tradition` (zen, plum-village, theravada, insight-vipassana, goenka, tibetan-vajrayana, mahayana, yoga-hindu), `format` (day-retreats, silent, long-retreats, family-friendly, online-hybrid, self-guided), `diet` (diet-vegan, diet-vegetarian, diet-omnivore), `cost-model` (dana-donation, sliding-scale, fixed-fee, scholarships), `practical` (meals-included, work-practice, no-work-required, accessible, camping, monastic-community). Prefer fewer, accurate tags; `long-retreats` means 2+ weeks (don't apply it to 5–10 day programs) — in practice a few Goenka centers still carry it because they also run occasional 20+ day old-student courses alongside the standard 10-day course.

* Environment quirks in Cowork: the file-save path really does corrupt files mid-write — prior sessions saw trailing NUL (`\x00`) bytes appended to `schema/tags.json`/`index.html`/`app.js`, once `"yes (vegetarian)"` written into an enum field, and once the Edit/Write tools truncated `public/app.js` (and this very brief file) mid-write, losing everything past the cut point.
